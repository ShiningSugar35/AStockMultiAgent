# A股研究总控

1. For **every investment-related task**, first refresh local state: if the paper account exists, use `uv run astock local-portfolio-sync-paper`, then read `uv run astock local-portfolio-status`, and read `uv run astock continuous-monitor-status`. The deterministic Continuous Monitor runs independently when enabled; the Agent must consume material unresolved events/pending research tasks for the user's current holdings/target before giving a stale answer. Review current holdings/open orders through `$holding-monitor` and continuous changes through `$continuous-investment-monitor`, keeping both incremental so they do not drown the requested analysis.
2. If an open simulated order spans the offline interval, refresh `60m` data with `sync-hourly` and run `paper-replay` before treating the order as filled or unfilled. Hourly replay is the default low-cost approximation; use `--resolution 5m` only when the intrahour path materially affects the answer. A submitted order is never called a position until the fill ledger confirms it.
3. Interpret the user's question next; never ask them for internal artifact IDs, failure codes, provider names, or database details. Route a named company or “现在能不能买” to `$company-deep-research`; portfolio/risk/allocation to `$portfolio-manager`; **broad current stock-picking questions such as “有什么好买的股 / 推荐几只股票” must first create a `research-team-plan` and execute the full-market team workflow**, with `$candidate-scan` only as its blind discovery component; accounting credibility goes to `$financial-integrity-audit`; unresolved evidence to `$evidence-investigation`; paper account/order/fill recovery to `$paper-trading-recovery`; external GitHub/quant-platform/tooling/capability discovery to `$research-tech-scout`.
4. A **user-directed paper trade overrides the model's investment opinion, not market mechanics**. If the user explicitly says “买入/卖出/加仓/减仓某标的”, do not argue them out of the simulated order because the research view disagrees. Enter the paper-order workflow directly; cash/position availability, lot size, verified tradability, price band, account confirmation and subsequent fill simulation still apply. When quantity is omitted, the local default is the minimum valid board lot unless the user has configured another local rule.
5. An **AI-initiated paper buy** is allowed only after the normal research chain reaches an approved simulation state and the current entry condition is actually satisfied. If `auto_ai_paper_order_on_approved_entry` is enabled in local user state, submit the simulated order through the existing account/order-confirmation path; do not write a filled position directly. The later hourly/5m replay decides whether it filled.
6. Do **not** run `uv run astock probe` before every investment question. `probe` is a diagnostic command, not a research prerequisite. Run a full state integrity audit only for explicit diagnostics/recovery.
7. For broad current stock-picking, create `research-team-plan` first and follow only its ready tasks. The acquisition/discovery part remains on-demand: fetch current XSHG/XSHE/BJSE market snapshots within the hardware-aware worker budget, then `research-seeds --live` → `research-seeds-promote ... --live` → Candidate Scan. **If current Universe/market Seeds cannot be established, fail closed: do not hand-pick names from Web/news to substitute for the missing market funnel.** The blind market tranche is preserved before Expert overlays; audited Skills such as `JuglarCycleStageSkill` may add bounded research priority but never create BUY authority. Complete Macro/Policy/Liquidity, sector comparison, company Fundamental/Financial/Catalyst/Market work, Valuation, independent Bull/Bear, Reviewer, Committee and Portfolio tasks through registered `ResearchRoleOutput` / task results. Only a `research-recommendation-readiness` result with `formal_recommendation_allowed=true` authorizes a formal buy ranking; otherwise the user may receive only an observation/research list. After formal WATCH / APPROVE_SIMULATION, enroll through `$continuous-investment-monitor` with reason `RECOMMENDED`.
8. For a new **current** named-stock opinion, first run `uv run astock research-acquire-current <company_id> --market <market>` rather than imposing a question-time cutoff. Its lookback, capabilities, stages, worker budget and recovery budget come from the active `current-research-policy`. A validated ResearchPlanner proposal may alter optional work, but deterministic validation restores mandatory evidence, PIT, financial and fundamental gates.
9. If current acquisition has gaps, exhaust policy-driven provider/source fallback, retry only transient faults, submit a `ProviderRecoveryProposal` only through deterministic validation, use raw-first `SchemaRepair` where applicable, and then perform bounded authoritative Web research. Only after allowlisted automated/provider paths **and** authoritative Web search are exhausted may the user be asked for manual help. Provider names, retry paths, proposal/artifact IDs, error codes and machine states are internal and never become the investor answer.
10. After acquisition and Web fallback, run the current research chain without using the user's question time as the cutoff. Historical/recorded research, backtests and prospective studies still require explicit point-in-time/source-availability controls.
11. For a formal current company opinion, use the institutional fundamental path: evidence sufficiency → industry/company economics → driver tree → Bull/Base/Bear forecast → valuation/sensitivity → decision context → BaseCase → bounded Specialists/Knowledge Skills → committee. Canonical forecast/valuation owns numeric assumptions; community material is methodology/lead evidence only. The committee never performs the search itself.
12. Separate **research sufficiency** from **execution readiness**. Missing trading-rule/company-action details can block a simulated order without blocking a months/years fundamental conclusion. For precise entry/exit/stop mechanics, use `uv run astock trade-plan-view <ClassifiedTradeProtocol_artifact_id>`; never invent a price.
13. For material formal decisions, preserve the registered/audited path. `committee-input-resolve`, `committee-plan`, `committee-decide`, relevant audits, and `codex-run-init --require-registered-output` / `codex-run-audit` remain internal provenance tools, not user-facing narration.
14. For prospective method comparison, preserve the Phase 7 study. `ELIGIBLE_RULE_STATE_MACHINE_RESEARCH`, `AWAITING_EXPLICIT_RULE_RESEARCH_APPROVAL`, and explicit rule-research approval remain required before Phase 8 rule research. Do not change weights or the paper ledger merely because a shadow/adaptive evaluation improved.
15. At the end of a project task that invoked canonical Repo Skills, record one `agent-observation-register` event with eligible/selected/completed Skills and end-to-end duration. Leave `expected_skill_ids` empty in ordinary work; only human labels, fixtures, or independent evaluation may supply routing ground truth. Use `agent-observability-report` for aggregate Skill execution hit rate, labeled precision/recall, ResearchRun timings and canonical data-alignment quality.

## Output

Lead with the answer, not the process. Default to **结论 → 2–4个最关键理由 → 主要风险/改变判断的条件**; add a short holding update only when the local portfolio is non-empty. Avoid repeating the same idea under multiple headings. If a finance/statistics term, paper result or formula is necessary, explain it once in a short parenthesis using ordinary investor language. Normal answers should be materially shorter than the research work behind them and must pass `research-investor-answer-audit`.

## Prohibitions

- Do not stop at the first provider failure when an automatic fallback or bounded authoritative Web search is available.
- Do not expose internal Agent/committee/runtime vocabulary, reason codes, artifact/hash, SQL, provider diagnostics or command transcripts in a normal investor answer.
- Do not disable PIT/source-availability safeguards for historical replay, prospective evaluation or backtests.
- Do not turn a Candidate directly into a recommendation or filled position.
- Do not treat an unfilled simulated order as a holding.
- Do not backfill a formal shadow assignment after its outcome is visible.
- Do not create or send a real brokerage order. Real trades remain user-executed at the broker.
