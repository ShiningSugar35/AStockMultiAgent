## 3. 增量和幂等实测

首次同步 600519 得到 432 根 canonical。第二次按检查点只回看 7 天，两源各请求 241 根，但合并后的 canonical 仍保持 2026-07-01 09:35 至 2026-07-13 15:00 的 432 根；第三次相同增量运行的 manifest 内容哈希与第二次完全一致。

Provider 批次身份只由请求和规范化柱子决定。会变化的服务器响应外壳仍作为独立 SHA-256 原始快照保存，但不再制造虚假批次版本。任一 Provider 失败且已有 canonical 时，旧 manifest 和 Provider 游标都不推进；两源恢复后重新发布 canonical 并由恢复任务接管检查点。录制夹具同时覆盖 ConnectError、ReadTimeout、429 和畸形响应。

## 7. 完成性补强

- Codex 完成一次成功导入后，运行目录八类文件齐全；RunManifest 记录成功状态和工件哈希。同一封存草稿重复导入得到相同哈希，Artifact Registry 不重复写入。
- `PolicyEngine` 在持久化前拒绝任何 Codex 请求命令；包含 evidence_id 的工件必须提供非空定位信息。
- `CommitteeAccessPolicy` 在 Schema 层禁止 network/API/MCP/Browser/全文和新研究能力，缺证据动作固定为 `NEEDS_INFO`。
- `CollectionCheckpoint` 覆盖 author、content_type、listing_page、listing_cursor、content_id、comment_page、comment_cursor、nested_reply_cursor，按作者、类型和内容唯一恢复。
- SourceAccessRouter 已验证 API 优先、MCP 先于 Browser、自动能力不足时转 Manual，并将选择和回退链落库。
- 逐条证据与后续阶段边界见 `docs/M1完成性审计.md`。
