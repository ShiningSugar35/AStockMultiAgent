# Phase 3 M3.2 / M3.3 开发计划

计划日期：2026-07-17
状态：M3.2、M3.3 均已完成并验收；Phase 3 完成
前置基线：M3.1 提交 `884a5b2`，Python 3.12.10，SQLite migration 0001～0010

## 1. 目标与非目标

本阶段把 M3.1 的“单期确定性勾稽”扩展为可审计的跨期、同行和异常检测闭环。所有结果仍是研究线索，不直接修改风险硬阻断、模拟账本或真实订单。

必须完成：

1. M3.2：TTM、同比、环比、每股值；同公司跨期比较；明确同行样本口径与分位；Beneish、Piotroski、Altman、Sloan、DuPont 的完整字段门禁、版本化公式和行业适用性。
2. M3.3：稳健 Z-score、Isolation Forest 和至少一个 PyOD 模型；冻结训练输入、固定随机种子、版本化模型工件、可重复推理、误报解释和冻结评测集。
3. 所有输入继续经过来源快照、PIT 和 Evidence 门禁；缺字段、样本不足、未来数据、行业不适用或模型不可训练时显式 `NEEDS_INFO`/`INSUFFICIENT_DATA`，不得补数。

不做：

- 不输出“财务造假已确认”；异常只表示需要检查。
- 不用 PyGOD，不建设图数据库。
- 不把社区内容当作财务报表事实。
- 不自动生成真实或模拟交易指令。

## 2. M3.2 数据合同

### 2.1 财务字段与期间语义

扩展 `FinancialFieldCode`，覆盖完整公式所需的折旧、销售管理费用、固定资产、长期债务、市值、发行在外股份等字段。持续期间项目必须显式声明：

- `STANDALONE_PERIOD`：该季度自身发生额，可直接滚动为 TTM；
- `YEAR_TO_DATE`：年初至报告期累计值，必须先与同年上一累计期作差；
- `INSTANT`：资产负债表时点值；
- `REPORTED_PERIOD`：来源未给出足够语义，只允许原值和安全的年度比较，不推导 TTM/环比。

### 2.2 同行样本

同行样本必须带 cohort_id、行业 Profile、指标/公式版本、报告期、as_of、公司 ID、值和 Evidence/PIT/SourceSnapshot 引用。服务只接受：

1. 同一行业 Profile；
2. 同一指标和公式版本；
3. 在审计 as_of 前可得；
4. 公司 ID 唯一；
5. 达到配置的最小样本数。

否则不计算分位，并留下具体缺口。分位采用稳定排序和中秩百分位，同值不因输入顺序改变结果。

### 2.3 输出

增加跨期指标、同行分位和完整评分输出；每个输出保存输入 fact/evidence、公式版本、期间、cohort 或缺口。已有 `FinancialIntegrityEvidencePack` 向后兼容。

## 3. M3.2 算法与门禁

| 能力 | 公式/规则 | 最小门禁 |
|---|---|---|
| TTM | 最近四个独立季度之和，或经过同年累计差分后的四季度之和 | 四个连续季度、期间语义明确、无重复/缺口 |
| 同比 | `(本期-上年同期)/abs(上年同期)` | 同口径上年同期，分母非零 |
| 环比 | `(本期-上期)/abs(上期)` | 连续季度、同口径，分母非零 |
| 每股值 | 金额/期末或配置指定股份数 | 股份数大于零、单位明确 |
| Beneish M | 标准 8 变量模型 | 当前与上期完整字段，金融行业排除 |
| Piotroski F | 9 项二元信号 | 当前与上期完整字段，金融行业排除 |
| Altman Z | 上市制造业 5 因子版本 | 市值和完整资产负债字段，金融行业排除 |
| Sloan | `(净利润-CFO)/平均总资产` | 当前/上期资产与当期利润、CFO |
| DuPont | 净利率 × 资产周转率 × 权益乘数 | 平均资产/权益可得且分母非零 |

阈值来自版本化配置。房地产、早期生物科技和 `OTHER` 必须保留行业解释或禁用未经校准的旗标。

## 5. M3.3 模型合同

### 5.1 特征与数据集

模型输入只来自 M3.2 已校验的数值特征。冻结数据集清单包含：dataset_id、feature schema、样本 ID、as_of、训练/评测分割、输入对象哈希和 Evidence 引用。排序规则固定，不依赖文件遍历顺序。

### 5.2 模型

- Robust Z-score：median/MAD；MAD 为零时显式不可训练或使用配置化 IQR 退化，不除零。
- Isolation Forest：固定 `random_state`、树数、抽样和 contamination；保存库版本与参数。
- PyOD：选择确定性、CPU 低成本模型作为第二视角；保存包版本、类名和参数。

任一第三方模型缺包、版本不符、样本不足或特征非有限时必须失败为明确 capability/data gap，不能输出伪分数。

### 5.3 异常解释

每个异常输出保存模型、版本、分数、阈值、触发特征、Evidence 和适用限制。误报解释只在有证据时生成，候选包括高增长、并购/资产重组、业务季节性、地产项目会计、早期研发期和会计政策变化；没有证据则保留为待核查，不自动“洗白”。
