## 1. 实际交付

1. 增加冻结异常数据集合同：固定行业 Profile、同行 cohort、特征表、样本 ID、训练/评测分割、目标样本、`as_of`、公式版本以及 SourceSnapshot/PIT/Evidence 引用；目标样本不得进入训练集，训练集与评测集不得重叠，未来或非有限数值会被拒绝。时序模型只选目标公司的更早期间，同行模型只选目标报告期的其他公司，二者不能混用口径。
2. 实现三种低成本 CPU 模型：median/MAD（必要时 IQR 退化）的稳健 Z-score、固定随机种子的 Isolation Forest、PyOD ECOD。配置保存在版本化注册表 `configs/financial_anomaly_models.yaml`。
3. 训练排序、随机种子、单线程执行和依赖版本均固定。同一冻结输入重复执行会得到相同数据集哈希、模型身份、序列化对象哈希、异常分数和评测结果。
4. 冻结数据集与序列化模型进入 ObjectStore 和工件注册表；模型清单记录作用域、特征、样本、参数、库版本、数据集哈希和模型对象哈希。migration 0012 增加数据集与模型工件清单，migration 0013 无损补充模型作用域，migration 0014 无损补充行业与 cohort 身份；旧库只做向前追加升级。
5. `FinancialIntegrityEvidencePack` 新增时序异常、同行异常、模型工件、冻结评测和有证据的正常情境解释。异常只表示“需要核查”，保持 `advisory_only=true`，不判断欺诈、不改变风险硬阻断、模拟账本或订单。
6. 训练样本不足、公式版本冲突、未来信息、快照/PIT/Evidence 不可用、特征非有限或模型不可训练时，系统显式输出 `NEEDS_INFO` 与具体数据缺口，不生成伪分数。

## 2. 冻结评测

测试夹具使用两个互不混淆的训练口径：目标公司 20 个历史期、同报告期 20 家其他公司；时序和同行评测各有 2 个正常样本与同一个异常目标。异常目标只在评测/推理侧，不进入训练。三种模型均独立生成模型工件、目标判断和混淆计数，并验证：

- 重复运行结果完全一致；
- 所有模型和数据集对象可通过 SHA-256 校验；
- 异常结果带原始 Evidence 引用与触发特征；
- 有“高增长”解释时，只有另有证据才能生成正常情境解释；
- 样本不足时不输出模型工件或异常结论。

该夹具仅用于验证系统行为，不代表真实公司的财务判断，也不用于拟合生产阈值。
