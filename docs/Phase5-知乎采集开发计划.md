## 2. 完成定义

“采集完成”必须同时满足：

- 从第一页连续枚举到平台明确的终止条件；
- 每个成功响应先进入 ObjectStore，再推进对应检查点；
- 每个内容 ID 都有成功、失败、受限、重复或更新状态，不能凭空消失；
- 回答带问题 ID、标题、URL 与必要问题上下文；
- 评论原始分页完整保存，作者参与链另行派生，不能只留摘要；
- 每位作者、每种内容类型都有 `AuthorCollectionCoverageReport`；
- `403`、`429`、登录失效、安全验证或结构异常不能被算成“内容为 0”或“已经到底”；
- 原文、Cookie、浏览器 Profile 和私有材料不进入 Git、日志或测试夹具。

只有报告达到 `PAGINATION_COMPLETE` 或经过结构校验的 `CONFIRMED_EMPTY`，且 `missing_count=0`，才允许标记完整；否则保持 `PARTIAL` 或 `ACCESS_RESTRICTED`。

## 3. 访问顺序与认证边界

每次访问都通过 `SourceAccessRouter` 记录决策，固定顺序为：

1. Python `httpx` 的已验证结构化请求：优先尝试无需复制浏览器 Cookie 的公开/当前可访问接口，单线程、低频、可缓存。
2. MCP：只有存在已验证、能返回同一结构化内容的连接器时才使用；没有可用能力就记录并继续。
3. 已登录 Chrome/Browser：若结构化请求需要现有登录态，在页面上下文中发起同源请求并保存响应；不导出、打印或持久化明文 Cookie。
4. 人工任务：只处理身份歧义、验证码、必须由用户确认的登录或平台限制。

不伪造签名，不绕验证码，不轮换账号或代理规避限速，不使用重试风暴。默认每个作者串行采集、请求间隔可配置且不低于平台实测安全下限；收到限制后立即停止相关来源。

## 4. 数据合同

新增并版本化以下合同：

- `KnowledgeSourceDefinition`：白名单身份、主页、url token、权限、允许内容类型与本地替代来源。
- `ZhihuAuthorIdentity`：平台用户 ID、url token、显示名、主页、头像/简介哈希、确认依据和状态。
- `ZhihuListingPage`：作者、内容类型、请求游标、下一游标、`is_end`、内容 ID 列表、原始对象哈希和结构版本。
- `ZhihuContentRecord`：回答/想法/文章的稳定 ID、作者、标题或问题上下文、URL、创建/更新时间、正文对象哈希、原始快照 ID和版本关系。
- `ZhihuCommentPage` 与 `ZhihuAuthorParticipationChain`：父内容、根评论/回复游标、作者参与位置、上下文节点和原始对象哈希。
- `AuthorCollectionCoverageReport`：发现、调度、成功、失败、受限、重复、更新、缺失、最后游标、终止条件与缺口。

正文不放入 SQLite。SQLite 只保存任务、游标、版本、对象哈希、计数和错误元数据；原始 JSON/HTML 进入不可变 ObjectStore；规范化内容索引写入 runtime 下的 Parquet。DuckDB 只读这些 Parquet 事实，不复制正文。

## 5. 检查点与恢复

检查点分四层：

1. 作者 + 内容类型的列表游标；
2. 单个内容详情状态；
3. 单个内容的根评论分页游标；
4. 单个根评论的嵌套回复游标。

一次边界提交的顺序固定为：接收响应 → 分类 HTTP/结构状态 → 原始字节写 ObjectStore → 校验对象哈希 → 登记 SourceSnapshot/内容版本 → 更新计数 → 提交检查点。任一步失败都不推进游标。崩溃恢复从最后已提交边界重试，同一响应保持幂等，不重复计数。

内容的 `updated_time` 或正文哈希变化时保留旧版本并新增版本；列表重复但正文未变计入 `skipped_duplicate_count`。失败游标进入 `collection_gap`，成功补回后关闭缺口，但不删除历史失败记录。

## 6. Python 采集器实现

模块放入 `src/astock/knowledge/`，拆成：

- 配置加载与白名单门禁；
- HTTP/Chrome 响应传输接口；
- 知乎响应结构适配器；
- 作者身份发现与验证；
- 列表、详情、问题上下文、评论和回复枚举器；
- ObjectStore/Parquet/SQLite 仓储；
- 覆盖报告与恢复服务。

稳定 CLI 计划为：

- `astock knowledge-source-list`
- `astock zhihu-author-probe <source-id>`
- `astock zhihu-author-sync <source-id> [--content-type ...] [--max-pages ...]`
- `astock zhihu-coverage <source-id>`
- `astock knowledge-local-coverage <source-id>`

`--max-pages` 只用于低频 smoke，不得把主动截断报告成分页完成。生产全量同步从检查点继续，直到真实终止、受限或明确失败。

## 8. 测试与验收门

日常测试只使用人工构造的 recorded fixture，不提交真实作者正文。必须覆盖：

- 成功响应先存对象、后推进游标；
- 写对象后崩溃、写元数据前崩溃和检查点后重跑；
- 正常分页、确认空、重复游标、意外空页、字段缺失和结构变化；
- `403`、`429`、登录页、验证码页、超时和网络中断分类；
- 内容更新保留旧版本，重复内容不重复计数；
- 回答问题上下文、评论分页和嵌套回复恢复；
- 两个同名候选不能自动确认；
- Windows 中文路径、原子写、Parquet Schema 与 SQLite 外键；
- Git 隐私扫描确认无正文、Cookie、Profile、PDF、DOCX 或 runtime 泄漏。

低频 live smoke 必须显式启用，只抓最小页数验证结构并保存私有 runtime 快照。全量采集完成后，再运行全仓 `pytest`、`ruff`、`pyright`、SQLite 完整性、对象哈希和每作者覆盖审计。
