# Public Response Contract v1

## 1. 目的与边界

本合同定义 AStockMultiAgent 的唯一公共输出边界。它只投影既有冻结研究、组合、持仓、监控和模拟账户事实，不创建第二套事实源、Provider Router、Evidence、研究状态或交易账本。

- 普通投资问题默认 `INVESTOR`。
- 只有用户明确肯定地要求查看、检查、排查或调试内部状态时才进入 `DEVELOPER`。
- 系统自身出现错误、文本中被动包含 `provider / traceback / 数据库 / 接口错误`，以及“不要看日志”“不需要调试”等否定表达，均不得触发 Developer Mode。
- 两种模式都不得暴露 Secret、Cookie、Token、密码、请求体或私人绝对路径。
- 展示层不得改变研究、推荐或模拟账本边界；当前产品没有真实券商执行能力或对应权限字段。

## 2. 唯一规范字段

`src/astock/schemas/presentation.py` 是公共输出合同的唯一 Schema 源。`presentation.py` 和所有调用方只能使用该文件中的模型，不得在服务或测试中复制平行字段。

| 语义 | 唯一规范字段 | 兼容读取 | 规范序列化 |
|---|---|---|---|
| 方向事实 | `direction_terms` | `directions` | 只输出 `direction_terms` |
| 投资结论 | `headline` | `conclusion` | 只输出 `headline` |
| 用户期望详略 | `requested_detail` | 无 | `SHORT / STANDARD / DETAILED` |
| 主体 | `subject` | 无 | 必填 |
| 结论强度 | `conclusion_strength` | 无 | `UNSPECIFIED / NOT_CERTIFIED / LOW / MODERATE / HIGH` |
| 估值或赔率 | `valuation_or_odds` | 无 | 受限列表 |
| 报告引用 | `report_reference` | 内部可输入 `report_path` | 只输出安全文件名，不输出绝对路径 |

旧字段别名只用于反序列化兼容。调用方同时提交冲突的新旧字段时必须拒绝，而不是任选其一。

当前版本：

- `response-context-v1`
- `fact-fingerprint-v2`
- `research-narrative-bundle-v1`
- `investor-presentation-v1`
- `developer-diagnostics-v1`
- `presentation-audit-v1`
- `rendered-response-v1`

## 3. 公共投影的强制内容

`InvestorPresentationModel` 使用 allowlist，只允许：

1. 主体或公司名称；
2. 结论；
3. 结论强度；
4. 估值或赔率；
5. 最多若干条非关键理由；
6. 最大风险；
7. 改变判断的条件；
8. 数据截至时间；
9. 必要引用；
10. 安全化后的正式报告文件名。

只要源叙事提供了风险、变化条件、数据时点、估值/赔率、引用或报告引用，这些内容即属于强制字段。长度控制不得删除它们。对于 `FULL_RESEARCH_RECOMMENDATION / DEEP_RESEARCH / FORMAL_REPORT`，多个已冻结风险与多个改变判断/失效条件必须全部进入公共投影；可去重，但不得静默丢弃。`FULL_RESEARCH_RECOMMENDATION` 必须自然呈现投资预期及其来源语义、具备可核实共同期限时的目标收益路径，以及可用时的情景盈亏/收益率、下行风险与目标缺口；目标年化明确为规划目标而非收益承诺。隐私采用偏松且 request-aware 的最小规则：荐股规划本金/预算、目标盈利、推荐配置金额/建议股数、证券公开单价以及发行人财务和股东公开数据都属于可展示的研究/方案信息；只有来自真实或模拟账户、既有持仓的个性化本金/成本、账户资产/现金、当前持仓数量和实际持仓盈亏默认不主动展示。用户本轮若明确提及、询问或要求查看某类账户/持仓数值，公共投影可以从已核实的 canonical 私有记录中展示对应类别，不得以“隐私”为由拒绝用户主动查询自己的数据。旧记录只改变公开投影，不回写原始工件、经济事实或哈希；隐私审计只阻断未被本轮用户请求授权的个性化账户事实，并不得把隐私处理谎称为投资研究资料缺失。

material investment request（荐股、买卖判断、持仓处置、组合推荐）统一使用 `FULL_RESEARCH_RECOMMENDATION`，只有最终 `RecommendationResearchReceipt + Publication Gate` 允许 investor view 后才进入本合同。Seed/Candidate/Acquisition/Team/Committee/Portfolio 中间态不具公共投资结论资格；展示层不得用“下一步可以继续研究”把上游仍可自动完成的工作转交用户。完整但非交易决策型公司研究可使用 `DEEP_RESEARCH`；`COMPANY_QUICK_VIEW` 只服务非决策快速事实/研究。canonical narrative 已明确 task type 时，网关只能升级到对应决策级预算，不得反向降级或改变研究事实。

## 4. 事实等价门

事实保护由两个方向共同构成：

1. **禁止新增**：输出事实必须属于源叙事允许的事实集合；
2. **禁止删除或替换强制事实**：所有 required fingerprint 必须完整出现在最终输出。

锁定维度包括：

- 主体/公司名称等已知实体；
- 六位证券代码；
- 数值、百分比、金额、倍数；
- 日期和时点；
- 买入、卖出、加仓、减仓、持有、观望等方向；
- 结论强度；
- 引用；
- 风险、估值/赔率、变化条件、数据时点等规范化锁定短语。

任一维度被新增、删除或改变时：

- `fact_equivalence_status=FAIL`
- `fact_drift_detected=true`
- `safe_to_send=false`
- 网关不得发送原稿，只能进入安全降级。

### 4.1 自然中文与表达返修

Investor Mode 的默认成品应接近成熟投研团队的研究说明：先给判断，再解释依据、条件与风险；语气克制、谦和、可讨论，不使用营销式口号，也不虚构“教授、从业者、亲历者”等身份。表达可参考耐心的经济学教师，但这只是文风要求，不是身份声明。

- 机械的“不是……而是……”“……，而不是……”、连续排比、空泛升华、翻译腔、装饰性粗体/破折号和模板化结尾属于 style QA；它们本身不是数据缺口，不能触发 `NEEDS_INFO`、降低既有结论或丢弃整篇已经通过事实门的报告。
- 默认读者没有政治、经济学或行业知识背景。高阶金融术语确有必要时保留，并在首次出现的段落内用一句话简释；常用术语不做教科书式重复解释。
- 自然化最多进行有界的同会话表达返修，只能调整语序、节奏和措辞。证券代码、数字/单位、日期、来源、因果、情景概率、交易方向、结论强度、风险、失效条件和引用仍受事实等价门保护。
- 普通投研结果以看涨、看跌或继续观察的清楚判断开头；有可靠依据时附合理估值区间和假设。删除无投资信息量的运行流水、重复自我免责和通知状态解释，保留真实负面财务事实、风险与反证。
- 不引入第三方 Humanizer 运行时或第二套生成器。统一编辑器 `src/astock/research/public_polish.py` 已供 ResponseGateway、InvestorAnswerGateway与定时研究通知共用；不走网关的 Agent 可通过 `astock investor public-polish TEXT_FILE` 对本地草稿执行同样的自然语言整理。该命令只处理表达，不代表研究已经完成或具备发布权限；直接在外部模型宿主发送的自由文本无法由项目 Python 自动拦截，应由 Agent 按 AGENTS.md 规定在发送前使用本命令或等效网关。
- 原始草稿若尚未通过事实/隐私审计，不能因为“文风自然”而绕过安全门；已经通过事实门的文本若只有风格告警，则保留事实并继续表达返修或安全发送，不能错误替换成“资料不足”。

### 4.2 结构化事实绑定与返修回退

`ResearchNarrativeBundle.fact_bindings` 复用当前叙事，逐项绑定 entity / metric / period / unit / value / qualifiers / citations 与完整 statement。所有字段和引用必须出现在该原句；最终文字仅允许忽略空白的原句匹配，不把同一数字集合当作关系正确的证明。未提供结构化绑定的旧生产者同样在润色前冻结实际选中的 headline、理由、估值、风险和改变条件；required fingerprint 直接来自这些源字段，不取自待审的 renderer 或润色结果。最终展示仍须保留这些关系，不能靠在其他位置保留相同数字绕过。网关另以润色前选中的源陈述覆盖最终正文，只额外允许固定展示标签及策略中的术语解释；保留原句后追加新实体、指标、确定性或无依据判断也会被拒绝。此检查是保守的源片段覆盖，不是通用语义推断；无法确认的改写回退原文，不追加模型裁判。

Gateway 在 polish 之前冻结源叙事；编辑后的文字必须同时满足原源与绑定约束。换证券、换财年/单位、删除否定/条件、改变可能性/因果或挪用引用时拒绝该改写。先尝试从同一冻结原叙事生成、重新审计可发送文字；只有原叙事也无法安全呈现才用安全摘要。不能拿润色后的文本审核自身，也不能为文风失败伪造数据缺口。自由文本未结构化部分仍需抽查，此实现不声称识别全部开放语义。

表达沿用现有确定性 editor，不新增默认模型调用，不调用 DeepSeek 生成或润色。参考 [SEC Plain English Handbook](https://www.sec.gov/files/handbook.htm) 与 [SEC Plain Writing](https://www.sec.gov/about/plain-writing-initiative) 的清晰主体、简短句子和明确限制。配对评价沿用现有冻结评测入口；没有人类评分/真实模型费用轨迹时，不声称偏好改善或节省比例已经验证。

### 4.3 数据缺口的自然语言投影

公共回答不得出现 `need_info`、reason code、artifact、stage、task/daemon、数据库或内部恢复过程。仅当某项缺口已明确依赖用户私人事实、文件或必要授权时，才提出具体最小需求；不为已知私有缺口重复无效公共检索，也不停止仍可独立推进的研究。公开来源暂不可用、真实公开路线耗尽或资源预算耗尽均不能被翻译为私人材料义务。保留已核验结果与其适用范围，公开结论只覆盖有证据支持的部分；继续可增加有效证据且未超预算的 fallback。公开采集的时间或轮数预算结束后，已取得原件仍可完成纯本地解析与准入；正式投资结论仍须满足原发布合同。

### 4.4 有来源的公开路线完成证明

`CurrentResearchContinuationService` 与真实 `InvestorOrchestrationService.closure_status` 共用 `recovery_evidence` 的只读投影，直接从已有 acquisition report/schedule、provider 原始响应、Web checkpoint/result 和 ObjectStore 核验公开补证路线。投影有报告数、操作数和原件字节上限；截断、缺失或损坏均保持未完成，不因为“扫描到这里”为止而断言资料不存在。每条路线保留尝试次数、响应分类、证据增量、来源 hash 和尚未覆盖的影响，无新事实表或恢复调度器。

只有同一请求、公司/市场、任务和派发代次的所有适用路线都实际成功返回已核验的空结果，并且没有未消费线索，才可形成有界的 `PUBLIC_DATA_UNAVAILABLE`。失败响应、UNKNOWN、超时、限流、预算终止、未尝试 fallback 和前一代空回传均不能充当证明；真实成功空回传只解除该完成操作的等待，不清除后续未知操作。发现链接但尚未读原件属于未完成线索。证明仅覆盖实际查询的范围，不宣称互联网已搜尽或发行人从未披露。

公开 facade 忽略调用方单独传入的 `automatic_resolution_exhausted=true` 权威声明，重新校验已登记证据。多公司请求必须逐公司覆盖；仅阻断确实依赖该缺口的后代，独立能力继续推进。预算结束仍为预算状态，私有资料需求沿原私人事实规则处理。上述机器诊断留在 Developer Mode，投资者仅看到已有结论的范围、缺失事实及其影响；不得用内部回执/代次细节代替正常研究回答。

旧 v1 回执曾把预算结束记作公开资料不可用。读取这类带预算标记但没有路线证明的记录时，只在内存投影为预算状态；缺失的具体限额原因明确标记为旧版预算状态，原对象、checkpoint、请求、deadline 与尝试额度均不改写。新版写入仍须真实路线证明，兼容读取不能授予公开来源穷尽结论。

## 5. 长度治理

允许的压缩顺序：

1. 去除精确或高相似重复理由；
2. 按任务预算减少非关键理由数量；
3. 保留所有强制字段和必要引用；
4. 若强制内容本身仍超过预算，返回固定安全摘要。

禁止通过删除风险、改变判断的条件、数据时间、估值/赔率、引用、主体、结论或结论强度来满足字符预算。`COMPANY_QUICK_VIEW` 继续保持紧凑；`FULL_RESEARCH_RECOMMENDATION` 使用完整投资决策预算（当前最多 16 条去重后的决定性研究维度），`DEEP_RESEARCH` 保留完整非交易公司研究预算；两者都必须保留全部已冻结风险/失效条件。只有用户明确要求 SHORT 时才进一步压缩非关键理由，不能把 material investment request 默认压缩为轻量答复。

`PresentationAudit.budget_status` 明确区分：

- `WITHIN_BUDGET`
- `EXCEEDED`
- `SAFE_FALLBACK`

## 6. 模式识别

Developer Mode 只接受肯定式用户动作，例如：

- “请查看日志”
- “帮我排查接口错误”
- “检查数据库状态”
- “调试这段流程”

以下情况保持 Investor Mode：

- “不要看日志”
- “不需要调试”
- “别进入开发者模式”
- “为什么这只股票下跌”
- 系统错误文本自动进入提示，例如 `provider timeout`、`Traceback` 或“数据库连接失败”

显式 `explicit_mode` 仍可由受控调用方指定；系统错误本身不具备切换权限。

## 7. 安全降级

普通投资者、Agent 对话与正式研究报告统一使用 `src/astock/research/public_polish.py` 的轻量公开表达处理，再走现行事实/隐私审核。可修正的内部运行术语、机械状态叙述、冗余免责和风格问题应自动删改，不能因为文风或出现一个技术词就阻断完整研究的交付，也不能把表达缺陷谎称为投资资料不足。修订须保留证券身份、财务数字与单位、合理估值、真实负面判断、来源引用、风险及结论方向；系统运行细节不得混入公共输出。所有研究及展示入口复用同一修订能力，不另造并行事实源。

Secret、私有路径和未获授权的账户信息须先从可发送文本中脱敏，不得泄漏；公开事实和必要风险应尽量保留。若正式投资研究尚未达到发行/发布门、事实冲突无法解决或规范强制信息经过有界修订仍不能安全呈现，才使用对应的安全摘要而不得回显不安全的原稿。这是事实/权限边界，不应当成额外的文风拦截器。

必要安全降级只保留：

- 经独立审计安全的主体；主体本身异常时固定为“研究对象”；
- 与实际问题相符的固定降级文本，不能虚构“资料不足”；
- `NOT_CERTIFIED` 结论强度。

绝对报告路径只用于内部审计允许列表；公共模型仅保留文件名。

## 8. CLI 兼容合同

原机器命令维持 `investor-research-view-v1` JSON：

- `research-investor-view`
- `research-acquisition-investor-view`

新增公共展示入口：

- `research-public-view`
- `research-acquisition-public-view`

新增入口统一经过 `ResponseGateway`。不得把旧机器命令的 JSON 偷换成新的公共投影。后续其它模块应采用同样原则：机器诊断/状态命令保持稳定，公开展示使用独立命令或显式 `--public`。

## 9. 审计输出

`PresentationAudit` 必须显式给出：

- 事实等价状态；
- 是否发生事实漂移；
- 强制内容是否完整；
- Secret 是否暴露；
- 私人路径是否暴露；
- 内部实现是否暴露；
- 字符预算及预算状态；
- 是否可发送；
- 是否回显原稿。

## 10. 验证门

本合同的参数化样例不少于 150 个，覆盖：

- 普通投资者问题；
- 肯定式和否定式诊断意图；
- 普通“为什么”；
- 系统错误文本；
- 套话、中英混排、符号与内部词；
- 主体、代码、数值、日期、时点、方向、引用、结论强度漂移；
- 估值、风险、变化条件、数据时点删除；
- Secret 和私人路径；
- 安全降级不回显；
- 长度压缩只删除非关键理由；
- 旧机器 CLI 合同与新增公共命令。

任何公共输出合同修改都必须同时通过参数化合同测试、相关产品化回归、Ruff、Pyright 和 `git diff --check`。
