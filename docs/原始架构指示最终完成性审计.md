原始指示同时包含两类要求，必须分开验收：

1. **立即交付项**：修订完整开发计划、完成 Phase 0 实测、建立 Codex 原生项目结构，并立即完成 Phase 1 / M1 的确定性基础设施、双源未复权 5m、账本、恢复、CLI 和测试。

因此，本次“通过”表示：

- 立即交付的计划、Phase 0 和 M1 已有实际代码、运行时和测试证据；
- 后续能力已进入明确 Phase、Schema、访问与验收契约；
- 后续尚未开发的功能继续如实标为未完成，没有用文档描述冒充实现。

它不表示 Phase 4～8 已经开发完成，也不表示知乎线上历史全集或方法蒸馏已经完成。

## 3. 开发计划冲突修订结果

`开发计划.md` 已更新至 v1.6，并形成以下唯一口径：

1. 主运行模式是 Codex 原生交互；Python CLI 负责可重复的数据、计算、校验、风险、状态和账本。
2. Python 固定 `>=3.12,<3.13`；不安装 Python 3.11，不依赖 FinRobot。
3. 默认行情链是东方财富主源、Sina 备用/交叉验证的未复权原始 5m。
4. 免费 1m 不进入默认链。只有同一根 5m 同时触及止盈和止损时，才允许经 `SourceAccessRouter` 尝试局部合格 1m 诊断；若不可得、受限或质量失败，则采用更不利的 5m 主结果、保留乐观敏感性结果并记录歧义原因，绝不补造价格路径。
5. 委员会只读冻结工件，禁止重新联网、重新抓取或发起新研究；缺证据返回 `NEEDS_INFO`。
6. 白名单作者历史全集是正式 Phase 5 范围；M1 交付的是可直接复用的安全采集和恢复底座。
7. 真实交易永远需要用户在券商端人工确认；当前项目没有自动向券商发单的接口。

新增 `tests/unit/test_original_instruction_contract.py`，把这些关键口径以及所需 Schema 字段、枚举和隐私规则锁成自动契约，防止计划与实现以后悄悄漂移。

## 4. M1 实现证据

### 4.1 Codex 原生入口与受控写回

- 根规则：`AGENTS.md`。
- Repo Skills 共 8 个：研究编排、候选扫描、公司深研、财务可信度、持仓监控、知识摄入、模拟盘恢复、证据调查。
- `CodexRunService` 建立 request、input manifest、context budget、run manifest、draft、validated result、citations 和 summary。
- `PolicyEngine` 拒绝 Codex 草稿携带命令；Schema、引用和策略校验通过后才能注册工件。
- 相同草稿重复导入保持幂等；Codex 不直接修改账本。

### 4.2 状态、对象存储和可恢复性

- `ObjectStore` 使用 SHA-256 内容寻址，原始响应不可覆盖。
- SQLite migrations 0001～0010 管理任务、尝试、游标、检查点、租约、幂等键、工件、来源快照、证据和模拟账本。
- 当前运行库 `PRAGMA integrity_check = ok`，`PRAGMA foreign_key_check = []`。
- ObjectStore 和 StateStore 测试覆盖幂等、原子写入、失败回滚、Windows 路径和 UTF-8 中文文件名。

### 4.3 双源未复权 5m

- EastMoney 和 Sina 只接受 `5m + NONE`，统一输出 `MarketDataBatch/MarketBar`。
- 原始 HTTP 响应先写 ObjectStore，再产生 Provider observation；质量门禁通过后才发布 canonical manifest。
- 质量报告覆盖 requested/actual 范围、时间语义、单位、缺失/重复、OHLC 合法性、延迟和双源差异。
- Provider 失败不会推进游标，也不会覆盖已验证 canonical；没有静默插值逻辑。
- recorded fixture 覆盖正常、429、畸形 JSON、连接错误、读取超时和响应外壳变化。
- live smoke 覆盖沪市、深市、创业板、科创板、北交所、指数和 CNINFO；北交所单源边界被显式记录。

### 4.4 模拟账本和回放

- `LedgerService` 在单个事务中追加 journal 和双重记账 entries。
- 现金、冻结现金、费用、订单、部分成交、持仓、NAV、T+1 和公司行为接口均有 Schema、migration 和测试。
- `PaperReplayService` 使用 canonical 未复权 5m，逐柱推进 checkpoint，重复恢复不产生重复成交。
- 项目只有 paper account 服务，没有自动实盘下单接口。

### 4.5 白名单采集基础设施

- `CollectionCheckpoint` 覆盖作者主页、内容列表、内容详情、评论分页、嵌套回复、作者参与链、失败重试和终止条件所需的 8 级游标。
- `AuthorCollectionCoverageReport` 区分完整、确认空、失败、受限、未知和部分覆盖；失败或空响应不能被解释成“没有内容”。
- 原始响应必须先进入 ObjectStore，再推进 checkpoint；403、429、登录失效、验证码或结构异常必须暂停，不能绕过。
- 完整知乎线上历史采集尚未执行，继续列为 Phase 5 未完成项。
