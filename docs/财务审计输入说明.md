# 财务可信度审计输入说明（M3.1）

## 这条命令解决什么问题

`financial-audit` 不负责猜数字，也不直接从网页抄表。它接收已经完成官方来源登记、不可变快照、PIT 时间标注和 Evidence 定位的财务数字，然后用 Decimal 做单位归一化、三表勾稽和描述性比率复算。

完整机器可读格式以命令输出为准：

```powershell
uv run astock financial-audit-schema
```

## 前置顺序

1. 通过 Phase 2 的官方公告/财报入口登记并解析文件；
2. 给每个拟使用的数字建立页或块级 `evidence_id`；
3. 建立对应 `source_snapshot_id` 和 `pit_id`，其中报告期、发布时间、系统可得时间必须真实；
4. 生成 `FinancialAuditRequest` JSON；
5. 运行审计并用返回的确定性 `audit_run_id` 查询恢复状态。

```powershell
uv run astock financial-audit .\request.json
uv run astock financial-audit-status <audit_run_id>
```

## 每个数字必须说明的内容

- `fact_id`：本次输入中唯一且稳定的数字身份；
- `company_id`：公司代码或系统统一公司 ID；
- `period_start` / `period_end` / `period_type`：数字覆盖的报告期；
- `statement_type` / `field_code`：来自哪张表、是什么科目；
- `reported_value` / `unit`：原披露数字和原披露单位；
- `source_snapshot_id`：不可变原始文件快照；
- `pit_id`：发布时间、可得时间和修订链；
- `evidence_ids`：能准确回到原文件位置的官方证据。

`CNY`、`THOUSAND_CNY`、`TEN_THOUSAND_CNY`、`MILLION_CNY` 和 `HUNDRED_MILLION_CNY` 会统一换算成元。不同单位表达的同一个数字不会被误判成冲突；同一报告期同一科目存在不同官方值时，系统不会擅自选一个，而会生成 `document_conflicts` 和人工核验任务。

## 返回状态

- `SUCCEEDED`：所选 M3.1 规则需要的数字、证据和 PIT 均可用；这不代表公司“没有风险”。
- `NEEDS_INFO`：存在缺字段、弱证据、未来信息、来源链不一致、官方值冲突，或用户点名了尚未实现的 M3.2/M3.3 能力。
- `risk_level`：只由已完成且证据充分的确定性规则触发；缺资料本身不伪装成高风险。

社区文章只能作为调查线索，不能作为已报告财务数字的主证据。M3.1 的比率仅做复算，不使用尚未校准的行业阈值；同行分位、时间序列异常、Isolation Forest 和 PyOD 仍明确禁用。
